## Safety boundaries for the new update

- Build/test all new destructive-reset behavior only in isolated deployments.
- Production reset and0.6.0 publication/deployment require separate explicit Owner authorization under the new brief; do not execute them during implementation.
- Full reset previews owned AI storage/DB categories and retained backups. Never traverse user-provided paths or remove accounts, projects, chat, billing, consent, binaries or platform security configuration.
- Existing reversible GENESIS is not evidence of complete deletion. New reset must invalidate outstanding jobs, block automatic reinitialization, verify cleanup and disclose retained/offline copies.

## Phase 8 — Project Intelligence

Implemented deterministic local Python/JS/TS import analysis, configuration/dependency evidence, framework detection, potential issues with source lines, directory counts, inspected files, incremental changes, relevant-file retrieval and direct dependents. Code → Project exposes refresh, confirmed decisions, search and deletion; legacy device-wide notes remain explicitly separate. This is static evidence, not execution or compiler validation; alias/generated imports can remain unresolved. Analysis is bounded to 1,000 eligible UTF-8 files of 400 KB each and respects ignore/secret/outside-workspace exclusions.

Existing chunk retrieval and memory classes are reused in private profile databases. Verified `/v1/me` identity binds rotated sessions to the same profile; unavailable identity uses an isolated session cache. Caller-provided identity claims are ignored. Requests bind to the initiating profile; late UI responses are masked after profile/project changes. Project Cloud sharing is now profile-scoped. Legacy device-wide consent records are preserved but require explicit reapproval because they have no trustworthy account binding. No project data is uploaded by analysis. Coding tasks capture their inference endpoint and refuse to send to a different signed-in account.

Deleting intelligence removes indexed chunks and this project's profile memories, preserves project files, and records a disabled tombstone so background refresh/agent retrieval cannot silently recreate deleted data. Explicit Refresh enables indexing again. Deletion is refused while coding tasks are active. These are local cache deletion guarantees, not forensic deletion of external/device backups.

## Phase 10 — Dataset Quality Studio

Data now includes read-only raw-source quality inspection and cleaning previews, prepared-dataset integrity/compatibility inspection, and tokenizer encode/decode previews. Dataset cards show example counts, train/validation tokens and whether the matching tokenizer exists. Prepared inspection checks actual token/mask lengths against metadata, sampled vocabulary bounds and sampled split overlap, with sources/licenses, duplicate counts and preparation time. Unchecked validation overlap is explicitly labeled untested.

Raw inspection supports existing licensed source adapters plus robust per-line JSONL diagnostics, prompt/answer and conversation messages, invalid/empty records and roles, UTF-8 errors, exact duplicates, heuristic near duplicates, repetition, token length and exact overlap with selected independent validation records. Cleaning previews exclude exact duplicates/validation overlaps and malformed rows; originals are never overwritten. Inspection is capped at 1,000 records / 8 MB and clearly reports sampling limits; it does not certify full-corpus decontamination. Near duplicates and repetition are warnings requiring review. No dataset license or access restriction is bypassed.

Verification: 18 backend data/training/quality tests passed, including actual TXT/JSONL ingestion, derived cleaned records consumed by preparation, nonzero train/validation tokens, tokenizer round-trip, license/auth enforcement, invalid encoding, near duplicates and corrupt prepared-mask detection; quality UI regression and TypeScript passed. ## Phase 11 — Explicit full native AI reset

Added a separate Owner-only, recently reauthenticated full-reset API and Settings → Account → Advanced Native AI operations UI. The legacy reversible lineage workflow remains available under its explicit retained-model label. Preview inventories only fixed deployment-owned roots (`storage/models`, model `storage/uploads`, `lineage`, `evolution`, `coordinator`, `library`, `eval`), database categories, managed GENESIS backups and external originals. Preview does not stop training or delete data. Execution requires the exact typed confirmation and an unexpired Owner-bound reset ID. Backup erasure requires a separate selected scope and exact typed backup confirmation.

Execution persists a recovery fence, pauses evolution, cancels outstanding leases, waits for native HTTP/background work and local checkpoint/exit, stops stable/canary serving, removes owned artifacts and native database records/history, clears model pins and volatile model state, and verifies the empty inventory. Failures remain fenced and resumable using the same reset ID; no replacement model is created. Existing OS run locking serializes erasure/recovery. Settings, accounts/auth, billing/usage, projects, ordinary chat content, consent, signing keys and software are preserved. Only model references are removed from retained chat messages. Normal updates never invoke this operation.

Job IDs and internal release versions remain monotonic after deletion, including SQLite, so stale worker contributions cannot refer to new jobs/models. Worker heartbeat advertises a reset generation; claims require cleanup acknowledgement. Updated workers cancel current work, then remove only locally marked checkpoints belonging to that server/worker credential scope. Unbound legacy and other-scope caches are retained and reported. Offline/older workers remain visibly unacknowledged. Managed backups (unless separately approved), external originals, exported Desktop packages and infrastructure snapshots remain disclosed; completion certifies deployment-owned live storage, **not irreversible erasure of every physical copy**. The supported deployment runs one coordinator/web process; other processes that directly write the same storage must be stopped before an administrative reset. This change does not redesign the server into a multi-replica scheduler.

Sixteen reset/network regressions passed on SQLite; eleven reset/security regressions passed on local PostgreSQL. All 64 UI tests passed, including independent backup confirmation, plus TypeScript.
